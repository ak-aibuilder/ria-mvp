## 7. Known Data Limitations

Ordered by demo risk (highest first).

1. 🚨 **Eval 4 is likely to FAIL / FM-5 risk.** Raw descriptions are lean (median 21, max 41 tokens), so there is almost no prose bloat to compress. Adding Q&A + facets + relationships will grow most products' token count, making "positive token_reduction for every product" false. **Mitigations:** (a) reframe Eval 4 / the headline around per-query retrieval tokens, not per-product size; (b) or add a few genuinely verbose products so some show real prose→JSON reduction.
2. **Eval 1 can't test false positives.** Every product lacks Q&A (D3=0 for all 20), so the audit flags all 20, not a discriminated 8. Add ~12 products WITH valid `q_and_a` (or carve a sub-fixture) so "flag exactly 8, 0 false positives" is actually testable.
3. **All dynamic dimensions start empty.** D3/D4/D5/D6 = 0 across the board; D1 (~7.0) and D2 (4–8) are the only non-zero signals. Great for showing lift, but the pre-enrichment tier/score spread is compressed.
4. **Low price ceiling (≤ $80).** Every product is under $200, so Eval 3's price filter never excludes anything — it tests facet inference, not price-band discrimination.
5. **Shallow category + HTML descriptions.** Shopify `Type`/`Tags` are single-level so D1's category-depth points rarely trigger; `Body (HTML)` means raw token counts include markup.
