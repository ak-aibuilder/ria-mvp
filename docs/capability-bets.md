# Capability Bets

Features blocked by model limitations, not missing code. Populate as discovered
during the build — each row is a bet that a model capability (or its absence)
determines whether a feature can ship.

| Feature | Limitation | Model | Workaround | Status |
|---|---|---|---|---|
| Fast concurrent catalog enrichment | Groq free tier ("on_demand") caps at 8000 tokens/min; each enrichment call reserves ~2.3k tokens (max_tokens=2048 + prompt), so ~20 concurrent calls 429 immediately | `openai/gpt-oss-120b` on Groq | Throttle to 2 products in-flight (`PRODUCT_CONCURRENCY=2`) + SDK retry-on-429 with backoff (`max_retries=6`). Trades wall-clock for reliability. Removed by upgrading to Groq Dev Tier. | Mitigated (Step 2) |
| Positive per-query token reduction (the demo headline / Eval 4) | On the free-tier-limited live subset (8 products) the pre/post token comparison is a wash-to-negative (~-2.5% with controlled agent behavior). Offline the mechanism DOES favor post — `search_products` payload drops 325->89 tok (8->2 results via facet filter, -236/call, compounding) vs a +26/call `get_product_details` penalty — but two things mask it live: (1) gpt-oss doesn't reliably emit the facet filter (controlled-run post prompt tokens 4470 ~= pre 4422, so the 8->2 narrowing rarely fires), and (2) reasoning/completion tokens dominate and are noisy. | `openai/gpt-oss-120b` on Groq | Needs (a) steer the agent to ALWAYS filter on facets when the query names one (tool_choice / prompt / pre-parse query -> filters), (b) larger enriched catalog so the compounding search saving dwarfs reasoning noise, (c) report prompt/context + products-read as the robust signal, not total tokens. | Open (Step 4) |
| Live iteration / re-verification of the agent | Groq free tier also caps tokens-per-DAY at 200,000. Six cumulative live enrich+agent runs during Step 4 verification exhausted it (Used ~199.5k), blocking any further live gpt-oss calls until the daily reset. | `openai/gpt-oss-120b` on Groq | Iterate agent logic against a mocked/stub client (deterministic); reserve live calls for one final confirmation. Dev Tier lifts the cap. Offline diagnostics (pure tool functions + deterministic facet extraction) need no API budget. | Open (Step 4) |
